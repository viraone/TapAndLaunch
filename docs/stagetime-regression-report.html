    How to read it. Test IDs read SUITE-AREA-NNN (for example AUTH-VC-001 is Authentication, Verification code, case 1). Every case says what to Run it on (for example Mobile · iPhone Safari). Cases are grouped by feature, or switch to By platform to group by where they run. The earlier flat IDs (SU-, CL-, SD-, TL-) are kept in each case's detail as Legacy ID.

    Statuses. Pass: the tester reported it passed. Pass after fix: a problem was found, fixed, and passed on retest. Pass – to confirm: passed per a report or batch result not itemised in the record. Failed once: failed at least once; see the follow-up note. Verified (assistant): checked by the assistant, not the tester. Not run: not yet executed, or blocked by launch-day setup. Not recorded: run or implied, but no result was reported.

    Cases marked "Added to complete the platform matrix" are planned and have not been run. Automated checks (unit tests and browser-emulator suites) are tracked separately. Dates are Seattle time.
